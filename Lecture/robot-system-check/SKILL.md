# 로봇 시스템 검사

## 범위
- 상태 조회와 일시적인 센서 구독만 수행한다. 이동 명령, 토픽 발행, 서비스·액션 호출, 파라미터 변경, 노드 실행·재시작, 패키지 설치를 하지 않는다.
- 설정 파일이나 환경 변수를 변경하지 않는다. setup 파일을 임의로 source하지 않는다.
- ROS 조회에는 `--no-daemon`을 사용한다. 검사 프로세스 종료 외에 기존 프로세스를 종료하지 않는다.

## 절차
1. [로봇별 기준](references/robot-profile.md)을 읽는다. 사용자가 지정한 프로필이 있으면 그것을 사용한다. 빈 항목은 추정하지 않는다.
2. 스킬 폴더 기준으로 `bash scripts/collect.sh`를 실행한다. 출력은 관측 자료이며 자동 판정 결과가 아니다. 시각과 실행 위치(로봇 PC/실습 PC/컨테이너)를 함께 기록한다.
3. 환경 및 필수 노드·토픽을 기준과 비교한다. CLI 실패나 제한 시간 초과를 빈 목록으로 해석하지 않는다. 실행 중인 검사 도구의 임시 노드를 로봇 구성으로 세지 않는다.
4. 지정된 센서 토픽만 하나씩 검사한다. 미지정이면 센서 검사는 확인 불가로 보고하고 토픽 이름을 요청한다. 먼저 `ros2 topic info --help`와 `ros2 topic echo --help`로 옵션 지원을 확인한다. 조회에 필요한 옵션이 없으면 해당 검사를 확인 불가로 남긴다.

```bash
# /scan은 프로필에 지정된 실제 토픽으로 바꾼다. 발행자와 QoS를 조회한다.
timeout -k 2s 10s ros2 topic info /scan --verbose --no-daemon
# 새 메시지 한 건을 최대 10초 동안 구독한다. 배열 본문은 생략한다.
timeout -k 2s 10s ros2 topic echo /scan --once --no-arr --no-daemon --qos-reliability best_effort --qos-durability volatile
```

5. 예시의 10초는 관측 제한 시간이며 정상 기준이 아니다. 프로필의 관측 시간이 있으면 사용한다. 구독 QoS는 발행자와 호환되도록 검사 프로세스에서만 선택한다. volatile 구독은 과거 저장 메시지를 현재 수신으로 오인하지 않게 한다. 일회성 센서는 관측 시점에 따라 수신 여부를 판정할 수 없음을 기록한다.
6. 주파수 기준이 있으면 `ros2 topic hz --help`를 확인하고 제한 시간 내에 수신 주파수를 측정한다. `--no-daemon` 등 필요한 옵션을 지원하지 않으면 측정 불가로 남긴다. 구독자 측 관측값은 발행 주파수와 다를 수 있고 한 건 수신만으로 주파수·센서 정확성을 보장할 수 없다.

## 판정 및 보고
- **정상:** 해당 항목의 명시된 기준을 실제 관측으로 충족했다.
- **이상:** 검사 환경과 관측이 유효하며 명시된 기준을 위반했다. 로봇 하드웨어 고장으로 단정하지 않는다.
- **확인 불가:** 기준 미정, 도구·접근 권한 부족, 명령 실패, 발견 지연이나 QoS 문제 등으로 판단 근거가 부족하다. 미수신은 관측 시간과 오류를 적고 도메인·네트워크·발행자·QoS 확인을 안내한다.
- `ROS_DOMAIN_ID`나 `RMW_IMPLEMENTATION` 미설정만으로 이상 판정하지 않는다. 보이는 값과 실제 적용값을 구분한다.
- 환경·노드·토픽·센서 수신 항목은 생략하지 않는다. 다음 형식으로 한국어 보고서를 작성하고, 관측값에 관련 명령·수치·오류를 짧게 포함한다. 전체 정상은 모든 필수 항목을 확인했을 때만 선언한다.

| 검사 항목 | 관측값 | 정상·이상·확인 불가 | 다음 확인 방법 |
|---|---|---|---|
| 센서 수신 | 센서 토픽 미지정 | 확인 불가 | 프로필에 센서 토픽 지정 |

## 사용 예시
- “$robot-system-check로 실습 시작 전 상태를 점검해줘. 기준이 없는 항목은 확인 불가로 표시해줘.”
- “$robot-system-check로 점검해줘. 로봇 기준은 `my-robot.md`를 사용하고 설정은 변경하지 마.”
- 스킬이 아직 검색되지 않으면 “이 폴더의 `SKILL.md`를 읽고 로봇 시스템을 점검해줘.”라고 파일을 지정한다.

CLI 예시는 로컬 ROS2 Jazzy의 도움말로 확인했다. 다른 배포판에서는 실행 환경의 도움말을 우선한다.
