파라미터는 각 노드에 속하는 설정값입니다. Launch는 프로그램 실행과 인자·파라미터 등의 구성을 자동화합니다.

파라미터는 노드가 선언하고 허용한 범위에서 바뀝니다. 실행 중 변경 가능 여부도 구현에 달려 있습니다. Launch 파일은 Python·XML·YAML로 작성할 수 있습니다.

발행자가 제공하는 품질 ↔ 구독자가 요구하는 품질

QoS는 신뢰성·큐 깊이·지속성 같은 통신 정책입니다. 센서 데이터 프로파일은 최신성을 위해 Best effort를 사용합니다.

아래는 Reliability 하나만 비교합니다. 실제 통신은 다른 QoS 정책, 도메인, 발견 설정과 네트워크 상태도 영향을 받습니다. ROS_DOMAIN_ID는 통신 그룹을 구분하며 보안 경계를 보장하지는 않습니다.

Python은 ament_python, C++은 보통 ament_cmake를 사용합니다. package.xml에는 패키지 정보와 의존성을 선언합니다.

다음은 Jazzy·colcon이 준비된 Ubuntu/Bash용 독립 실습 예시입니다. 기존에 같은 이름의 폴더·패키지가 없다고 가정합니다. rosdep은 패키지가 선언한 외부 의존성을 준비하는 도구입니다.

cd ~/jazzy_comic_ws
colcon build --packages-select comic_bot

# 새 실행용 터미널
source /opt/ros/jazzy/setup.bash
source ~/jazzy_comic_ws/install/local_setup.bash
ros2 run comic_bot hello

tf2 · 좌표계 · 시각

“앞으로 1미터”는 누구 앞?

10-1
루키카메라가 “앞에 상자가 있어!”라고 했어요. 카메라는 옆을 보고 있는데요?

카메라의 앞 ≠ 로봇 몸체의 앞

10-2
토리tf2는 좌표계 사이의 관계를 시간과 함께 관리해. 관측한 시각에 맞춰 좌표를 변환하자.
map → odom　→ base_link　　 → camera_link

map → odom → base_link → camera_link

좌표값에는 기준 프레임이 필요합니다. tf2는 프레임 관계를 트리로 관리하고 점·벡터 등을 다른 기준으로 변환합니다.

그림의 트리는 흔한 구성 예시입니다. tf2 자체가 지도나 로봇 위치를 추정해 주지는 않습니다. 드라이버·로봇 모델·위치 추정 노드 등이 올바른 변환을 제공해야 합니다.

RViz는 3D 시각화 도구입니다. 센서 표시에는 토픽과 TF, Fixed Frame 설정이 맞아야 합니다. rosbag은 재현과 분석을 돕습니다.

아래 예시는 실제 /scan 토픽이 발행되고 있을 때 사용합니다. record는 Ctrl+C로 끝냅니다. 재생은 기록된 메시지를 다시 발행하는 것이며 물리 세계 전체를 복원하는 것은 아닙니다.

ros2 bag record -o comic_scan /scan
# Ctrl+C로 기록 종료 후
ros2 bag info comic_scan
ros2 bag play comic_scan
