01장비 정보를 공유하는 공통 언어

AAS는 제조 자산의 정보를 공통된 구조와 의미로 표현하고 교환하는 표준화된 디지털 표현입니다.

로봇·모터·센서의 사양, 상태, 문서 등을 다른 회사의 시스템에서도 이해하고 활용하도록 만드는 것이 목적입니다. 기본 개념과 구조는 IEC 63278-1에 정의되어 있습니다.

기계가 읽을 수 있는 ‘신분증과 정보 창구’
신분증으로 장비를 식별하고, 정보 창구를 통해 기술 사양·매뉴얼·운전 상태 등에 접근한다고 생각하면 쉽습니다.

왜 값만 전달해서는 부족할까요?

서로 다른 장비가 temperature, temp, 온도라는 이름으로 데이터를 보내면, 이름만으로는 모터 온도인지 주변 온도인지 또는 단위가 무엇인지 알기 어렵습니다.

AAS에서는 semanticId로 개념을 식별하고, 개념 설명과 ECLASS·IEC CDD 같은 사전을 활용해 의미를 명확히 할 수 있습니다. 같은 형식만 쓰는 것을 넘어 같은 템플릿과 의미 정의를 사용하는 것이 중요합니다.

03디지털 트윈에서 AAS의 역할

디지털 트윈은 현실 자산을 디지털로 표현하고 활용하는 더 넓은 개념입니다. AAS는 그 안에서 자산 정보를 표준화해 제공하는 기반으로 활용할 수 있습니다.

정적 정보

제조사, 사양서, 인증서, 매뉴얼처럼 자주 바뀌지 않는 정보를 제공합니다.

동적 정보

실제 장비와 연결하여 현재 상태나 측정값을 제공하도록 구성합니다.

기능·서비스

필요한 기능을 모델링하고 실제 구현과 연결해 외부에서 활용하도록 설계합니다.

AAS를 만들었다고 물리 시뮬레이션이나 예지보전 기능이 자동으로 생기지는 않습니다. 시뮬레이션 모델, 분석 로직, 데이터 수집과 동기화는 목적에 맞게 별도로 구현하고 연결해야 합니다.

04ROS2와 연결하는 방법

ROS2는 Topic·Service·Action으로 노드 간 통신과 로봇 기능을 구현합니다. AAS와 연결할 때는 필요한 데이터를 변환하는 노드를 두고, 외부 시스템이 사용할 정보 모델로 매핑할 수 있습니다.

아래 구성은 ROS2 학습 환경을 위한 설계 제안입니다. 공식 ROS2–AAS 표준 매핑이나 즉시 실행 가능한 구현을 의미하지 않습니다.

로봇·센서실제 자산
↔
ROS2 노드상태·기능
↔
변환 노드의미·단위 매핑
↔
AAS 서버표준 정보 제공
↔
공장 시스템조회·활용

예시: 배터리 상태 제공

  1. ROS2 노드가 배터리 상태를 Topic으로 발행합니다.
  2. 변환 노드가 메시지를 구독하고 값의 의미와 단위를 확인합니다.
  3. AAS의 운전 상태 Submodel에 값과 측정 시각을 반영합니다.
  4. 외부 대시보드가 AAS를 조회해 배터리 상태를 표시합니다.
설계 시 구분할 것
고속 모터 제어는 기존 제어 경로에서 처리하고, AAS에는 외부 시스템이 필요한 상태와 기능을 제공하는 구성을 권합니다. 연결이 끊겼을 때 오래된 값이 현재 값으로 오인되지 않도록 갱신 시각과 유효성을 함께 관리하세요.

추천 실습: 로봇 한 대의 명판과 배터리 상태

  2. 서버에서 조회: AAS 서버와 Web UI를 통해 모델을 확인합니다.
  3. ROS2 연결: 배터리 상태를 구독하는 변환 노드로 값을 갱신합니다.
  4. 검증: 값과 단위가 일치하는지, 데이터가 끊겼을 때 오래된 상태를 구별할 수 있는지 확인합니다.
