01

URDF는 무엇을 설명할까?

URDF는 로봇의 모양과 연결 구조를 기술하는 XML 파일 형식입니다. 보통 .urdf 확장자로 저장합니다. 로봇에 어떤 부품이 있고, 어디에 연결되어 있으며, 어떤 방식으로 움직일 수 있는지 표현합니다.

link = 하나의 부품

몸체, 바퀴, 로봇 팔의 각 마디, 센서처럼 하나의 강체로 취급하는 부분입니다. 각 링크에는 기준 좌표계가 있습니다.

joint = 부품 사이의 연결

부모 링크와 자식 링크를 연결합니다. 연결 위치와 방향, 회전·직선 이동 여부 등을 정의합니다. 움직이지 않는 고정 연결도 조인트입니다.

base_link (몸체)
├── left_wheel_joint  → left_wheel_link
├── right_wheel_joint → right_wheel_link
└── sensor_joint      → sensor_link

기본 URDF 구조는 하나의 루트 링크에서 뻗어 나가는 트리입니다. 위 이름들은 예시이며, base_link는 몸체 좌표계 이름으로 흔히 사용합니다.

기억할 점: URDF는 구조를 설명합니다. 실제 모터를 구동하려면 별도의 제어기와 하드웨어 연결이 필요합니다.

02

먼저 익힐 다섯 가지 요소

요소역할바퀴 로봇의 예
link로봇을 이루는 부품몸체, 왼쪽 바퀴, 센서
joint부모·자식 링크의 연결과 운동 방식바퀴 회전축, 센서 고정 연결
visual화면에 표시할 형상과 색상초록색 직육면체 몸체
collision충돌 검사에 사용할 형상몸체를 감싸는 단순한 상자
inertial질량, 질량 중심, 관성 텐서물리 시뮬레이션용 몸체 물성

visual, collision, inertial은 링크 안에 정의합니다. 시각화용 형상과 충돌용 형상은 서로 다르게 만들 수 있습니다.

자주 만나는 조인트 유형

유형움직임예시
fixed상대 위치·방향이 고정몸체에 장착된 센서
revolute각도 범위가 제한된 회전로봇 팔의 관절
continuous각도 제한 없는 회전구동 바퀴
prismatic범위가 제한된 직선 이동슬라이더
03

짧은 XML로 구조 읽어 보기

몸체 위에 작은 센서를 고정한 예제입니다. 링크 2개와 고정 조인트 1개로 연결 관계를 표현합니다.

<?xml version="1.0"?>
<robot name="study_robot">
  <link name="base_link">
    <visual>
      <geometry>
        <box size="0.4 0.3 0.1"/>
      </geometry>
      <material name="green">
        <color rgba="0.1 0.6 0.4 1"/>
      </material>
    </visual>
  </link>

  <link name="sensor_link">
    <visual>
      <geometry>
        <cylinder radius="0.04" length="0.06"/>
      </geometry>
    </visual>
  </link>

  <joint name="sensor_joint" type="fixed">
    <parent link="base_link"/>
    <child link="sensor_link"/>
    <origin xyz="0 0 0.08" rpy="0 0 0"/>
  </joint>
</robot>
  1. robot이 전체 모델을 감싸고, link 두 개가 부품을 정의합니다.
  2. box size는 x·y·z 방향 크기입니다. 이 몸체는 0.4 × 0.3 × 0.1 m입니다.
  3. parent와 child가 어떤 링크를 연결할지 지정합니다.
  4. 조인트의 origin은 부모 좌표계 기준 연결 위치와 방향을 정의합니다. 이 고정 조인트에서는 센서 좌표계가 몸체 중심보다 z 방향으로 0.08 m 위에 놓입니다.
  5. 기본 도형의 중심을 기준으로 몸체 윗면은 z = 0.05 m, 센서 아랫면도 0.08 − 0.03 = 0.05 m여서 맞닿습니다.

단위: 길이는 m, 각도는 rad, 질량은 kg입니다. rpy는 roll·pitch·yaw 회전각입니다.
예제 범위: 구조와 시각화를 위한 예제입니다. 물리 시뮬레이션에는 충돌 형상과 관성 정보 등의 추가 설정이 필요합니다.

04

ROS2에서는 어떻게 쓰일까?

URDF + 관절 상태모델 구조 + 현재 관절 값
→
robot_state_publisher링크 사이의 변환 계산
→
TF → RViz2좌표 변환 전달 → 시각화
  1. URDF 문자열을 robot_description 파라미터로 robot_state_publisher에 전달합니다.
  2. 움직이는 조인트의 현재 값은 /joint_states로 들어옵니다. 실습에서는 joint_state_publisher_gui, 실제 로봇에서는 하드웨어 상태를 전달하는 노드 등이 제공할 수 있습니다.
  3. robot_state_publisher는 고정 조인트의 변환을 /tf_static으로, 움직이는 조인트의 변환을 관절 상태에 따라 /tf로 발행합니다.
  4. RViz2는 로봇 모델 정보와 TF를 함께 사용해 부품의 모양과 자세를 표시합니다.

위 XML 예제는 모든 조인트가 fixed이므로, 링크 사이의 고정 변환을 발행하는 데 움직이는 관절 상태가 필요하지 않습니다. ROS2 동작 설명은 Jazzy 문서를 기준으로 정리했습니다.

RViz2는 시각화 도구입니다. 화면에서 모델의 자세가 바뀌는 것과 실제 로봇의 모터가 움직이는 것은 구분해야 합니다.

05

스스로 설명하며 복습하기

질문을 먼저 생각해 보고 펼쳐서 답을 확인해 보세요.

바퀴는 link일까, joint일까?

바퀴 부품 자체는 link입니다. 몸체와 바퀴 사이의 회전 연결은 joint입니다.

움직이지 않는 센서에도 joint가 필요할까?

센서를 별도 링크로 정의한다면 fixed 조인트로 몸체와 연결합니다. 조인트는 움직임뿐 아니라 연결 관계도 표현합니다.

visual만 있으면 충돌 검사와 물리 시뮬레이션이 가능할까?

visual은 표시용 형상입니다. 충돌에는 collision, 물리 계산에는 inertial 등 필요한 정보를 별도로 정의해야 합니다.

URDF만 작성하면 실제 로봇이 움직일까?

아닙니다. URDF는 모델의 구조와 속성을 기술합니다. 실제 구동에는 제어기, 하드웨어 인터페이스, 구동 명령 등이 필요합니다.

“link로 부품을 만들고, joint로 연결한다.”

이 문장을 이해했다면 URDF의 출발점을 잡은 것입니다. 다음 학습에서는 회전 조인트를 추가한 뒤, 반복되는 XML을 정리하는 Xacro로 확장해 볼 수 있습니다.
